# tls+h2

入口与出口之间使用 TLS 1.3 加密，通过 HTTP/2 双向流传输 TCP 业务。入口与出口均需 Agent `v0.14.0` 或以上；规则的目标地址由出口访问。

## 出口与监听配置

在出口的「节点管理 → 编辑」中设置：

| 配置项 | 用途 / 默认值 |
| --- | --- |
| 作为出口节点 | 开启出口转发。 |
| 传输协议 | 选择「tls+h2」（`tls_h2`），显示此协议的证书、客户端与流控配置。 |
| 隧道对外地址 | 入口实际连接的出口域名或 IP，不带协议和端口。可以与证书域名不同。 |
| 出口监听地址 | 出口本机绑定的 IP，默认 `0.0.0.0`。 |
| 出口监听端口 | 出口本机接收 TLS 隧道的端口，范围 `1–65535`。 |
| 允许哪些入口使用此出口 | 选择允许使用此出口的入口节点。 |
| 证书域名 / SNI | TLS 握手与证书验证使用的域名，必须被证书覆盖；不要填写 IP。 |
| 公网隧道端口 | 入口连接的对外端口；`0` 使用出口监听端口。NAT 两侧端口不同时填写公网端口。 |
| 证书模式 | 选择自签名、手动导入、HTTP 自动申请或 DNS 自动申请，详见下表。 |
| HTTP Path | 隧道 POST 请求路径，默认 `/api/stream`；以 `/` 开头，不含查询参数。主控自动给关联入口下发相同路径。 |
| HTTP Host | 隧道请求的 Host，与 SNI 独立；留空使用出口证书域名，可带端口。 |
| 伪装网站 | HTTP / HTTPS 网站地址。未认证请求反向代理到该网站；留空返回普通 404。 |

公网端口需要以 TCP 透传方式到达出口 TLS 监听器。节点通用选项见 [节点配置](./tcp.md#管理员节点配置)，入口关联方式见 [节点中转](../guide/tunnel.md)。

## 证书模式与配置

| 模式 | 作用 |
| --- | --- |
| 自签名 | 按证书域名自动生成证书和密钥，将公开证书下发给入口用于验证；无需手动填写证书。 |
| 手动导入 | 使用已有 PEM 证书链和匹配私钥；证书需覆盖填写的证书域名。手动更新到期证书。 |
| HTTP 自动申请 | 主控申请、续期证书，出口提供 HTTP 验证；域名需指向该出口，公网 `80` 可达。 |
| DNS 自动申请 | 主控通过 DNS 服务商创建验证记录并申请、续期证书；无需开放 HTTP 验证端口。 |

| 配置项 | 用途 / 默认值 |
| --- | --- |
| 证书链 PEM | 手动导入时填写服务端证书及中间证书，格式为 `BEGIN CERTIFICATE`。 |
| 匹配的私钥 PEM | 手动导入时填写与证书匹配的私钥。 |
| 可选私有 CA | 手动导入私有 CA 签发的证书时，提供公开根证书给入口验证；公共 CA 证书留空。 |
| ACME 邮箱 | 自动申请模式的账户联系邮箱。 |
| ACME Directory HTTPS 地址 | 证书签发服务的 ACME API，默认 Let's Encrypt 正式环境；一般保持默认。 |
| 节点 HTTP 验证监听端口 | HTTP 自动申请时，出口在本机接收 HTTP-01 验证的端口，默认 `80`。改为其他端口时仍需把公网 `80` 转发到它。 |
| DNS 服务商 | DNS 自动申请使用的服务商：Cloudflare、阿里 DNS 或 DNSPod。 |
| DNS 凭据 JSON | DNS 服务商的授权信息，键名见下表。主控使用这些凭据，不下发给节点。 |
| 可选 ACME 私有根 CA | 验证私有 ACME 服务 HTTPS 接口的公开 CA；使用公共 ACME 服务时留空。 |
| 可选签发根 CA | 私有签发机构颁发的隧道证书所需公开根证书，下发入口用于验证；公共 CA 留空。它与 ACME 服务接口的 CA 可以不同。 |

| DNS 服务商 | JSON 字段及用途 |
| --- | --- |
| Cloudflare | `api_token`：DNS 验证记录编辑 Token；`zone_token`：可选、用于读取域名区域的独立 Token。 |
| 阿里 DNS | `access_key_id`、`access_key_secret`：DNS API 的 AccessKey 凭据。 |
| DNSPod | `login_token`：DNS API Token，按服务商格式填写。 |

## 入口客户端配置

这些选项在入口节点编辑中设置，作用于该入口连接出口时的 TLS 握手和连接复用。

| 配置项 | 用途 / 默认值 |
| --- | --- |
| uTLS 指纹 | 可选关闭、Chrome 或 Firefox；新配置默认关闭，使用标准 TLS。已有 Chrome / Firefox 配置保留。 |
| 可选 SNI 覆盖 | 留空使用出口证书域名；填写后覆盖该入口连接各 TLS 出口时使用的 SNI 和证书校验域名，因此仍必须被出口证书覆盖。不会改变实际连接的出口地址。 |
| 每出口 TLS 连接池上限 | 同一入口到同一出口的物理 TLS 连接数量上限，默认 `2`，范围 `1–8`；多个业务流复用这些连接。 |

## HTTP2 流控

接收窗口设置用于入口客户端，出口使用普通 HTTP/2 默认接收窗口。

| 配置项 | 用途 / 默认值 |
| --- | --- |
| 每流接收窗口 / MiB | 入口客户端单个业务流可接收的流控额度，默认 `16`，范围 `1–64`。 |
| 每连接接收窗口 / MiB | 入口客户端单条 HTTP/2 连接中所有流共用的接收额度，默认 `64`，范围 `1–256`，且不能小于每流窗口。 |
| 每 TLS 连接并发流 | 出口认证后的单条 HTTP/2 连接业务流上限（同时受协议并发上限约束），默认 `256`，范围 `1–1024`；此项在出口生效。 |

窗口不是带宽限速值，增大可能增加内存占用；不确定时使用默认值。名称、目标负载均衡、Proxy Protocol 等规则选项见 [规则配置](./tcp.md#规则配置)，资源初始值来自套餐，管理员可调整个人限制。

出口的初始 HTTP/2 SETTINGS 使用普通 Go HTTP/2 网站的默认值，不随隧道窗口和业务流限制改变。SETTINGS 是 HTTP/2 建连必需消息，无法在 HTTP 请求认证前隐藏。出口默认接收窗口较此前减小，高延迟连接的单流上传吞吐可能受到影响；入口下载窗口仍可配置。

## 未认证访问与伪装

错误 Host、错误 Path、无效认证或重复认证统一访问伪装网站；认证头和隧道元数据不会传给网站。网站不可用或未配置时返回普通 404。

伪装网站使用 HTTPS 时，握手前识别出的 SNI、ALPN 或证书协商不匹配连接可直接转交该网站完成 TLS 握手。正常网站浏览支持 TLS 1.2 / 1.3，业务隧道始终要求 TLS 1.3 + h2。

TLS 已发出服务端握手数据后，后续握手失败不能重新转发到另一条 TLS 连接，也不能在无效 TLS 连接里发送网页；这类连接按标准 TLS 行为关闭。HTTP 网站仅支持握手完成后的请求回退。

旧节点不支持新配置时显示「节点需升级」，入口与出口均升级到 v0.14.0 后生效。uTLS 仅改变客户端握手指纹，不保证通信在所有网络中不可识别。

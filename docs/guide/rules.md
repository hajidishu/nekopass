# 转发规则

在「转发规则」添加规则，选择 TCP 或 UDP，再选择入口、出口，填写监听端口与目标地址，保存并启用。监听端口留空会自动分配。

同时转发 TCP 和 UDP 时，分别创建两条规则；同一个入口的 TCP 与 UDP 规则可使用相同监听端口。

升级时，原有合并规则自动拆成 TCP、UDP 两条，保留入口、端口、出口、目标和启停状态，各占一个规则名额。历史合计用量留在原 TCP 规则，UDP 规则从零开始统计；用户已用流量不变。导入旧版合并规则备份时也会自动拆分。

目标一行一个，支持域名、IPv4、IPv6：

```text
example.com:443
192.0.2.10:25565
[2001:db8::10]:443
```

以上地址仅为格式示例，请替换真实目标；`192.0.2.0/24`、`2001:db8::/32` 等文档保留网段默认被目标 IP 限制禁止。

客户端连接规则显示的入口地址与端口。直转时选择「不使用隧道，直接转发」；使用出口见 [节点中转](./tunnel.md)。

规则支持分组、复制、批量启停和 JSON 导入导出；每个账号只管理自己的规则，管理员在「用户管理」查看其他用户的规则。

## 暂停与恢复

单条规则点击操作栏的「暂停」图标，再次点击「恢复」即可解除暂停。批量操作先勾选规则，再点击上方「暂停选中」或「恢复选中」。暂停保留规则和已有流量统计，节点同步配置后停止转发并关闭现有连接。

管理员在「用户管理 → 转发规则」使用相同操作；管理员暂停后，用户仍可自行恢复。恢复后仍需满足套餐有效期、额度和节点权限。

## 导入与导出

默认导出 nyanpass 兼容格式，一行一个 JSON：

```json
{"dest":["example.com:443"],"listen_port":9122,"name":"示例","proxy_protocol":3}
```

导入时粘贴内容或选择文件，再选择入口、出口和分组。端口 `0` 表示随机分配，也可以勾选「重新随机分配监听端口」。最多 500 条，失败时整批回滚。

`proxy_protocol`：省略或 `0` 为关闭，`1` 为发送 v1 TCP，`3` 为发送 v2 TCP；`2` 按 v2 TCP 导入，当前不支持 UDP。`accept_proxy_protocol: 1` 开启接收，信任来源由管理员在「系统设置 → 转发安全」配置，用户导入的数据不能更改信任网段。

管理员可禁止转发到指定 IPv4 / IPv6 网段，节点会检查域名实际解析出的 IP。默认禁止本机、内网、链路本地、组播、云 metadata 等特殊地址；需要访问内网时，由管理员移除对应限制。

兼容格式不包含节点、分组、启停状态和接收版本限制。需要保留全部配置时，导出选择「Nekopass 完整备份」；旧版备份仍可导入。

## 账号与额度

规则跟随用户当前的个人额度、限速和节点组。套餐仅提供初始值；管理员自己的账号也需要套餐和节点权限。限制留空表示不限制，额度耗尽或套餐到期会暂停转发。

流量与带宽按双向业务数据合计。同一用户在同一入口节点共享带宽上限，不同节点分别限速。
